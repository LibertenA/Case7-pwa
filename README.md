# PWA для заявок на обслуживание

## Инструкция запуска
Требуется Node.js 18 или новее.
```bash
npm ci
npm run dev
```
Откройте адрес, который выведет Vite (обычно `http://localhost:5173`). Production-сборка: `npm run build`, локальный просмотр: `npm run preview`. Установка PWA — через `localhost` или HTTPS командой браузера «Установить приложение».

## Источник тестовых данных
Тестовые сущности создаёт сам пользователь через форму. Внешние датасеты и парсинг не используются, нейросетевая генерация не применялась. Встроенные реальные персональные данные отсутствуют. Для проверки следует использовать вымышленные названия объектов, описания и учебные изображения, на которые есть право использования.

**Обоснование:** вводимые вручную вымышленные заявки достаточны для проверки формы, локального сохранения, очереди несинхронизированных заявок и сценария offline → online.

**Этическая и юридическая оговорка:** не загружайте персональные данные третьих лиц; используйте только вымышленные данные и изображения, на которые есть право использования.

## Проверка offline-сценария
1. Запустите приложение и откройте раздел «Проверка offline-режима».
2. Включите переключатель `Offline` (принудительно блокирует отправку в демонстрационном сценарии).
3. Заполните часть формы и перезагрузите страницу — текстовые поля черновика должны восстановиться. Затем создайте заявку, при необходимости прикрепите файл.
4. Убедитесь, что заявка отображается как ожидающая отправки, а счётчик «Ожидают отправки» увеличился.
5. Перезагрузите приложение — заявка должна остаться в IndexedDB и снова отображаться в очереди.
6. Выключите переключатель `Offline` — приложение запустит синхронизацию автоматически (при необходимости нажмите «Синхронизировать»).
7. Убедитесь, что у заявки появилось состояние «Синхронизировано», а счётчик ожидающих отправки уменьшился.
8. Повторите синхронизацию — повторная отправка того же clientId должна вернуть ранее созданный serverId, а не создать дубль.
9. Дополнительно проверьте реальное отключение сети в DevTools → Network → Offline: отправка должна завершиться ошибкой, а заявка остаться локально в очереди.

Переключатель нужен для воспроизводимой демонстрации: `navigator.onLine` сообщает только о состоянии сетевого интерфейса и сам по себе не доказывает доступность сервера. Перед пометкой заявки как синхронизированной приложение выполняет сетевой запрос проверки доступности.

## Архитектура обмена данными
Клиент: React, TypeScript, Vite. PWA: Web App Manifest и Service Worker. Локальное хранилище: IndexedDB (заявки и вложения); черновик незавершённой формы — в localStorage. Демонстрационный серверный контур — mock API с проверкой доступности сервера; записи mock backend хранятся в localStorage текущего origin. Допустимые вложения: изображения и PDF до 10 МБ (файл сохраняется локально в IndexedDB и в mock API не передаётся). Очередь несинхронизированных заявок имеет состояния ожидания, ошибки и успешной отправки; отправка выполняется автоматически при восстановлении подключения, по сигналу Background Sync (при поддержке браузером) и вручную. Идемпотентность mock API обеспечена стабильным clientId — повторная отправка не создаёт новую запись.

**Ограничения:** mock backend не является полноценным удалённым сервером — записи доступны только в рамках того же origin и профиля браузера, обмен между устройствами не обеспечивается. Обычная вкладка и установленная PWA с одного origin обычно используют общее IndexedDB; при разных адресах (например, `localhost` и сетевой IP) хранилища раздельные. Обновление Service Worker не удаляет базу заявок. Background Sync поддерживается не всеми браузерами: Service Worker передаёт сигнал открытой вкладке, при закрытом приложении очередь отправляется при следующем запуске. Для промышленной эксплуатации необходимы отдельный REST backend, серверная БД, авторизация, разграничение доступа, проверка содержимого файлов и HTTPS.
